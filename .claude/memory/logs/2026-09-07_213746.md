## Found and fixed: the interior was never in EB Garamond

While checking the new page rendered, noticed the title-page subtitle was not italic —
then that *no* italic anywhere in the book was rendering.

Cause: `pdf.py` built its stylesheet as `CSS(string=print_css(), font_config=…)` with no
`base_url`. `@font-face` `src` URLs resolve against the **stylesheet's** base URL, not the
document's, so WeasyPrint dropped every `@font-face` rule (warning only, not an error) and
fell back to the system serif — DejaVu Serif, which on this machine has no installed
italic face. So the entire interior was set in the wrong font AND lost every italic.

Fixed by passing `base_url=str(c.ROOT)` to `CSS(...)` in `pdf.py`; `tools/chapter_pdf.py`
had the identical bug, so the 7-language review PDFs emailed last session were also in the
fallback serif. Fixed there too.

**Consequence: 327 pages → 271 pages.** Spine 0.8175" → 0.6775". Full cover
13.0675 × 9.25in → 12.9275 × 9.25in. Print cost ~$4.77 → ~$4.10. Any cover art built to
the old spine is wrong. `pricing-notes.md` still carries the ~$4.45/300pp assumption —
the generated KDP sheet now computes the delta instead of asserting it.

Lesson worth keeping: last session verified "rendered pages inspected as images, not
assumed" — but inspected them for layout, not for typeface. A silently-substituted font
looks like a perfectly good page.

## Front/back matter guidance (answered in chat, recorded for future reference)

- **Dedication** — one line, "For X". Author's own; optional. Nothing to translate.
- **Epigraph** — a book-level quotation before ch1. Optional and arguably redundant here:
  chapters used to carry their own epigraphs and the Fable restyle removed them.
  If used, real quotations need permission; public domain or the author's own is safe.
- **Index** — no. Indexes are for non-fiction. A novel needs no index and, at 55 chapters
  with numbered titles, arguably no printed TOC either (the EPUB nav is auto-generated).
- **Acknowledgments** — the author thanking people (editor, first readers, family), not
  reader feedback. Optional; back matter.

All four remain unwritten; the build drops placeholder-only pages and lists them.

## Session continued — cover lettering typeset at build time

User asked whether the cover title and byline could be set with tools rather
than regenerated as art, then: match the earlier (ChatGPT-made) front design,
and make translations get covers automatically from language + page count.

`tools/bookbuild/covertext.py` (new). `cover/` holds `*-raw-hires.png` (art, no
lettering) and `*-hires.png` (lettering burned in by an unreproducible scratch
session). The type is now set over the raw art at build time in EB Garamond,
palette sampled from the picture. `config.COVER_TEXT` switches back to "baked".

- **Barcode.** KDP fixes where the barcode prints — bottom-right of the back
  panel, 2×1.2in, 0.25in inset. What moved is the text: the back panel lays out
  above that block, shrinking the blurb a step at a time until tagline, body,
  closing line and byline all clear it. Same constant the proof draws, so the
  two cannot disagree.
- **Spine.** Cut from the front art's inner edge and lettered to the current
  spine width, so a page-count change re-letters it. Blank below 79 pages
  (KDP's own rule).
- **Translations need no artwork.** The art carries no words now, so an edition
  with nothing in `cover/<lang>/` falls back to the base art and still gets its
  own title, spine and blurb. Verified with a 5-chapter German edition and a
  German blurb, no German art: German front/spine/back, own cover PDF and
  proof in `build/de/`. Removed afterwards.
- Front geometry measured off the approved cover and pinned as fractions of the
  panel (`TITLE_TOP`, `DISPLAY_CAP`, `LINE_STEP`, `TITLE_MAX_W`). Sizing is by
  cap height, not point size, so the constants survive a change of face. Title
  is filled with a vertical cream→amber gradient, which is what makes it read
  as part of the painting rather than a caption laid on it.
- Ebook cover now comes from the same generated front (trimmed, no bleed).

### Follow-up: cover text legibility

User read the back panel as missing "by _horia". It was present — pale cream
set directly on the brightest column of the sun's reflection, which is nearly
the same value, so it read as absent. Two fixes in `covertext.py`:

- `_draw_over()` measures the art's mean luminance under each line and sizes
  the halo to it — barely there on dark sky, thick and repeated on a bright
  ground. All back-panel copy and both bylines now go through it.
- The back byline picks the darkest of seven candidate positions in the band
  the barcode leaves free, before the halo makes up the rest.

Also fixed: א was rendering skewed. The chapter-title style is italic, Hebrew
has no italic, and with no italic face declared for the Hebrew fallback the
renderer synthesised a slant on ALEPH's own signature (ch38 title, ch55
sign-off). `styles.py` now declares the italic face pointing at the same
upright file.

Verified for KDP: interior exactly 6.000 × 9.000in, 271pp, all four faces
embedded as subsets; cover PDF single page 12.927 × 9.25in; ebook cover
1707 × 2560 (above the 1000px minimum, though 1.5:1 rather than Amazon's
preferred 1.6:1 — offered to pad, awaiting the author).

### Back-panel layout corrected to the approved design

User compared against the original back cover and was right that it read better.
Two things the generated version had got wrong, both now fixed:

- **Tagline** was fitted to one small line. The original gave it two generous
  lines. `_tagline_font()` now picks the largest size that keeps it to two.
- **Body was centred.** Centring a multi-line paragraph leaves the eye no fixed
  left edge to return to; the original set the blurb flush left. Layout items
  now carry an alignment — tagline and closing line centred, paragraphs ranged
  left within the centred column.

`config.COVER_BACK_BYLINE` added. The back byline is trade convention, not an
Amazon requirement, and the name is already on front and spine — left True,

### Lettering colour and shadow matched to the approved covers

Author: the original reads more clearly because the text is yellow on a
blue-and-amber ground, with a slightly stronger drop shadow. Correct — the
generated palette was pulling the sampled highlight 52% toward white, which
gave a pale cream that washes out on the bright horizon.

Sampled the actual letter fills off the baked covers (median-cut clusters, not
the highlight edges, which had misled a first attempt):

    front title fill   (252, 213, 141)   -> INK_GOLD
    glyph-foot amber   (226, 166,  87)   -> WARM_GOLD
    back-panel copy    (254, 222, 109)   -> BODY_GOLD

`_palette()` now blends the art's own highlight hue 30% into those golds
(`ART_TINT`), so a differently-coloured edition still tints its lettering
without ceasing to read as gold. Back-panel copy takes the more saturated
`body` gold; the title keeps the ink→warm gradient.

Shadows: display shadow alpha 215→240, blur 16→13, offset 8→9, composited
twice so it reads as depth rather than haze; adaptive halo floor 120→160 with
one extra pass. Both panels rebuilt and inspected.

### Back-panel shadow and measure; full pipeline verification

- `BLURB_SHADOW = 1.6` — `_draw_over()` gained a `weight` that scales both halo
  alpha and the number of composites. The back panel carries a paragraph of
  small type over cloud and water and needs more behind it than a single
  display line on the front does. Halo floor also raised 160→175.
- **Type size was not the problem** — the blurb is 12.0pt, larger than the
  interior's 11.2pt. The *measure* was: 4.78in gave 77 characters a line, above
  the 60–70 the eye tracks. `BLURB_MEASURE` 0.78 → 0.71 → 4.35in, now min 48 /
  mean 64 / max 71 over 11 lines, with the body size untouched.
