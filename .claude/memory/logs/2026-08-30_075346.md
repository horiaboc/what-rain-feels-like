## Decisions / findings

- Canonical build artifact = `build/manuscript.md` (single compiled Markdown), which then
  renders to EPUB (KDP ebook), print-interior PDF, cover PDF, DOCX. Markdown as the hub
  because it is diffable and feeds translation / TTS / plagiarism check cleanly.
- **KDP has no public publishing API.** File prep is automatable; the upload flow is not,
  and scripted browser automation breaches KDP ToS. Not building that.
- **Spine width depends on interior page count**, so the wraparound cover PDF can only be
  finalised after the interior builds. Sequencing is forced: interior → page count → cover.
- Cover art headroom is thin: 6×9 with bleed needs 1837×2775 px at 300 DPI; the hires
  front is 1875×2811 (~2%). Fine as-is, but any regeneration should target ≥2000×3000.

## Built this session

`tools/bookbuild/` package + `tools/build.py` CLI. One command regenerates everything
from the chapter sources in ~16s.

- `config.py` — every publishing decision in one file (metadata, trim, margins, type)
- `sources.py` — parser; `{{TOKEN}}` substitution into book-matter from config;
  strips `*(guidance notes)*`; drops pages that are still placeholder-only
- `manuscript.py` — `build/manuscript.md` (the compiled single source) + `build/text/`
- `styles.py`, `html.py` — print and epub CSS, shared HTML assembly
- `pdf.py` — 6×9 interior, `epub.py` — EPUB3, `cover.py` — wraparound + proof,
  `docx_out.py` — editor DOCX, `meta.py` — KDP metadata sheet

Also: vendored EB Garamond (OFL) as static instances cut from the variable font with
fonttools, plus an 8 KB subsetted Frank Ruhl Libre carrying only א for the ch38 title.
`tools/requirements.txt` pins the toolchain. Removed `book-matter/01-half-title.md`
and `02-title-page.md` — now generated from config.

## Two WeasyPrint findings (established by experiment, not assumption)

1. `@page name:first` is **not** scoped per named-page group — a second named group's
   first page still gets the margin boxes. Chapter-opening running heads are therefore
   suppressed with `string(runrecto, first-except)`, which does work.
2. Element-level `counter-reset: page` is **ignored entirely**. Front matter and body are
   rendered as separate PDFs and concatenated with pypdfium2 so the story opens on
   folio 1; front matter is padded to an even page count to keep recto parity.

## Per-edition restructure (user request, same session)

Build output was flat `build/`; user asked that each language build into its own folder
so future translations stay separate. Restructured to a full per-edition model rather
than only splitting the output directory:

- `config.EDITIONS` — one entry per language (name, locale, title, subtitle, slug,
  scene break, ISBN). `configure(lang)` repoints sources, cover art and every output
  path. Called from `build.py` via `--lang`; `--editions` lists them.
- Sources: base edition stays at `chapters/` + `book-matter/` + `cover/`; translations
  at `translations/<lang>/…` and `cover/<lang>/`.
- Outputs: `build/en/`, `build/de/`, …
- EPUB identifier is uuid5 per language — deterministic across rebuilds, distinct per
  edition, so a translation is not a duplicate book in a reader's library.

Verified end-to-end with a throwaway German edition (3 chapters, placeholder cover art):
built to `build/de/` with German title/locale/slug and its own cover, distinct UUID,
`build/en/` untouched at 327pp. Test files removed afterwards.

`translation-plan.md` gained a "How a translation is wired into the build" section.
